# Pinned to the versions the committed sweep actually ran on, read out of
# results/artifacts/run_manifest.json. Install these before reporting that a
# number failed to reproduce.
#
#     pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cpu
#     pip install -r requirements-lock.txt
#
# Why pin at all: `pip install torch-geometric captum rdkit dive-into-graphs`
# resolves to a set that is NOT interchangeable, and one combination silently
# destroys a whole attributor.
#
# ONE PIN HERE DELIBERATELY DIFFERS FROM THE RECORDED RUN. The manifest for the
# committed sweep says captum 0.2.0, because `pip install dive-into-graphs`
# honours DIG's `captum==0.2.0` pin and downgrades whatever Captum was already
# installed. Captum 0.2 imports cleanly and then fails on every molecule: PyG's
# CaptumExplainer forces `internal_batch_size=1`, and Captum 0.2 slices the
# additional forward arguments along dimension 0 after expanding them, so
# `edge_index` arrives at `set_masks` with shape (1, E) instead of (2, E) and
# raises `IndexError: index 1 is out of bounds for dimension 0 with size 1`.
# Integrated Gradients is the only method in the sweep that takes
# `internal_batch_size`, which is why it alone lost all 204 of its cells while
# Saliency, InputXGradient and GuidedBackprop came through untouched.
#
# So: install DIG with `--no-deps` (molsanity imports SubgraphX without
# executing DIG's package `__init__`, so DIG's dependency list is not needed),
# and keep captum at the version below.
#
# torch itself is deliberately not listed here: the wheel differs by platform
# and accelerator, so it is installed separately from the PyTorch index. The
# sweep ran on torch 2.11.0+cu128 (GPU) and the CPU build of the same version
# reproduces it.
